# Samples wanted

Only three `.adt` files are publicly available (see `docs/FORMAT.md`). None of them has memo, money, timestamp, Unicode or deleted records. If you have **Advantage Database Server** or **Advantage Data Architect (ARC)** installed, you can close that gap in about 10 minutes.

## How to generate the samples

1. Create an **empty folder**, e.g. `C:\adt_samples`.
2. In Advantage Data Architect, open a connection to that folder as **free tables** (not a data dictionary), with table type **ADT**.
3. Open the SQL utility, paste the contents of [`generate_samples.sql`](generate_samples.sql) and run it.
   - Each table is independent. If a statement fails (some type keywords differ between ADS versions), **note the error message** and continue.
   - Do **not** pack `t_deleted`; it must keep its deleted record.
4. Optional, but very useful: in ARC, add one non-NULL row by hand to `t_raw` and `t_blob` (any few bytes) and write down the bytes you used.
5. Zip the folder: `.adt` **and** `.adm` files (`.adi` index files are welcome but not needed).
6. Open a "Sample submission" issue on GitHub and attach the zip, together with:
   - ADS / ARC version
   - character set of the connection (ANSI or OEM) and collation
   - any SQL errors from step 3

All values are synthetic, so nothing private is shared. **Never send real customer data.**

## For maintainers

- `samples/generate_samples.sql` and `samples/expected/*.json` are generated by `python tools/sample_spec.py`; edit the spec, not the outputs.
- Drop received `.adt`/`.adm` files directly into `samples/`. `tests/test_samples.py` picks them up automatically and compares them with the expected values.
- Some expected values are guesses (numeric layout, empty string vs NULL). When a real sample disagrees, the sample wins: update the spec and `docs/FORMAT.md`.
